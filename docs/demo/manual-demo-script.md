# SupportPilot 手动演示脚本（带旁白版）

这份脚本用于自己用 OBS / Windows 自带录屏（Win+G）录制一版带真人旁白的演示视频。
自动化录制版由 `frontend/record-demo.mjs` 产出（无旁白）；本脚本是同一链路的「逐屏讲解」版。

## 前置条件（已在运行）

- 后端：`http://127.0.0.1:8000`（uvicorn，确定性 Provider，不调用付费模型）
- 前端：`http://127.0.0.1:5173`（Vite）
- 数据库：PostgreSQL/pgvector 已完成 `alembic upgrade head` + `seed` + `ingest_knowledge --provider deterministic`

## 账号

| 角色 | 邮箱 | 密码 |
|---|---|---|
| 客户 | `alpha.admin@example.com` | `SupportPilotDemo!2026` |
| 支持人员 | `support.agent@example.com` | `SupportPilotDemo!2026` |

## 录制建议

- 分辨率 1920×1080（或至少 1280×720），16:9
- 只录浏览器窗口，隐藏书签栏（Ctrl+Shift+B）
- 总时长控制在 3 分钟内；每步停留 2~3 秒再操作，给旁白留气口
- 浏览器打开前先清掉无关标签页

## 演示链路（旁白要点见每步下方）

### 第 1 步：登录页（约 15 秒）

1. 打开 `http://127.0.0.1:5173`
2. 指出登录页只做账号密码 + 企业账号（OIDC）两个入口

> 旁白要点：这是一套面向 B2B API 平台的技术支持 Agent。登录入口除了本地口令，还支持企业单点登录（OIDC + PKCE）。

### 第 2 步：客户登录（约 20 秒）

1. 填客户邮箱 `alpha.admin@example.com`、密码
2. 点「进入工作台」
3. 指出顶栏出现「Alpha Admin（合成用户）」与角色

> 旁白要点：演示数据全部是合成数据。这里以客户身份登录。

### 第 3 步：带引用的知识回答（约 40 秒，重点）

1. 输入框已预填一个问题：「HTTP 429 响应里的 Retry-After 应该如何处理？」
2. 点「开始诊断」
3. 等右侧出现「引用证据」「逐条主张」和「Agent 执行轨迹」三块
4. 逐块指出：
   - **引用证据**：答案来自哪篇文档、哪个 chunk、源 URI
   - **逐条主张**：每一条结论都能追溯到引用（claim 级引用）
   - **执行轨迹**：能看到 Agent 内部调用了 `knowledge_search` 等工具，过程可解释

> 旁白要点：这里走的是「混合检索 → RRF 融合 → 重排 → 置信度门控」链路。回答不是模型自由发挥，而是抽取式原文 + 独立引用，任何一条命中 Prompt Injection 都会整体安全升级。

### 第 4 步：创建工单（约 30 秒）

1. 把输入框改成：「批量导出功能报错，请协助排查并转人工处理。」
2. 点「开始诊断」
3. 指出出现「写操作确认」的工单草稿，点「确认创建工单」
4. 指出出现「已按确认创建工单。」

> 旁白要点：创建工单是低风险写操作，必须经过确认 + 幂等键（Idempotency-Key），重复请求不会重复建单。高风险动作（退款、改权限、运维命令）会被直接拒绝，不会自动执行。

### 第 5 步：切换支持人员（约 20 秒）

1. 点右上角「退出」
2. 用支持人员账号 `support.agent@example.com` 登录
3. 指出界面从「客户工作台」变成了「工单队列」

> 旁白要点：同一个账号体系里，客户看到的是自助诊断，支持人员看到的是人工接管队列。这就是「自动回复 → 人工接管」的边界。

### 第 6 步：认领并推进工单（约 30 秒，重点）

1. 在「工单队列」里点刚创建的工单（摘要含「批量导出功能报错」）
2. 指出工单详情和状态轨迹，初始状态 `open`
3. 点「认领并分诊」，指出轨迹出现 `open → triaged`
4. 点「转为 in_progress」，指出轨迹出现 `triaged → in_progress`，状态徽标变为 `in_progress`

> 旁白要点：工单有明确的状态机（open → triaged → in_progress → resolved/…），每次状态迁移都落库、可审计，支持人员能清楚地追踪人工处理进度。

### 收尾（约 10 秒）

> 旁白要点：这是一套完整的纵向闭环——从用户提问、知识检索、置信度门控、自动回答，到建单转人工、状态推进，全链路可运行、可解释、可评测。项目用确定性 Provider 跑通全部 CI 和回归，并额外适配了百炼 Qwen 的意图分类，真实模型只做实验验证，不作为生产准确率宣称。
