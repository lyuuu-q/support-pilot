# ADR 0009：Agent SSE 中止与幂等重试

- 状态：Accepted
- 日期：2026-10-12

## 背景

Agent 已通过显式会话状态、工单幂等和确认 Key 支持跨请求恢复，但前端仍只能等待完整 SSE 结束。网络波动、用户离开页面或长时间等待时，无法主动停止；停止后也没有明确的“用同一意图安全重试”路径。

曾评估引入官方 PostgresSaver 实现节点级 checkpoint，但当前引入方式会导致依赖源全量改写，并且 checkpoint 表不由 Alembic 管理。现有业务恢复已足够覆盖确认和工单副作用，因此先补客户端中止与幂等重试，节点级 checkpoint 留到部署恢复需求明确后再做。

## 决策

1. 前端 `streamAgent` 接受 `AbortSignal`，用户可以主动停止等待。
2. 停止只终止当前浏览器请求，不假设服务器取消执行；提示用户服务器可能已经完成。
3. 确认工单的 `Idempotency-Key` 在首次确认时生成，并在重试期间复用；只有确认完成或开始新意图后才清除。
4. 普通问答重试继续复用原 `session_id`，由会话状态决定是补参、确认还是重新检索。
5. SSE 每条进度和结果增加 `id`，为后续真正断线续传保留协议基础；当前不声称已经实现服务端事件回放。
6. 不使用内存队列保存事件，不新增 checkpoint 表，不改变 Answerability 与工单状态机。

## 代价与限制

- 客户端中止时服务器可能仍在运行，运行状态可能保留为 `running`；
- 当前没有服务端事件回放或节点级恢复；
- 重试的幂等保证集中在工单确认和业务写操作，普通只读检索可能重复执行；
- 需要更强的部署恢复时，再引入 PostgresSaver 和独立迁移方案。

## 验证方式

- 前端测试确认 `AbortSignal` 传入 fetch；
- UI 测试覆盖停止、提示和安全重试；
- 确认重试复用同一 `Idempotency-Key`；
- 后端测试确认同一 Key 返回同一工单；
- 既有 E2E 和 80 场景评测不回归。
