# ADR 0013：前端 SSE 断线自动恢复

- 状态：Accepted
- 日期：2026-10-12

## 背景

后端已经持久化 SSE 事件并提供回放 API，也有运行级 checkpoint 恢复接口，但前端仍只显示网络错误，用户需要重新发起整轮请求。

## 决策

1. `streamAgent` 解析 SSE `id:`，通过 `onEventId` 回调把 `{run_id}:{sequence}` 交给调用方。
2. CustomerWorkspace 在网络错误且已知 run id 时自动进入恢复：
   - 调用事件回放 API 重新构建进度 Trace；
   - 如果事件中已有 result，直接恢复最终回答；
   - 否则调用运行恢复 API，从 checkpoint 继续并获取最终结果。
3. 用户主动中止不触发自动恢复，而是保留现有“停止/重试”语义。
4. 恢复成功后清除错误状态，显示“已从服务端恢复断线前的事件”。
5. 恢复期间继续使用原确认幂等 Key，避免重复工单。

## 限制

- 当前回放和恢复是两个 HTTP 请求，不是一条自动续传的 SSE 长连接；
- 只处理浏览器可识别的网络/流错误，不处理服务端永久失败；
- 回放接口最多返回 500 条事件，超大运行需要分页；
- 事件保留期限和清理策略尚未实现。

## 验证方式

- API 测试验证 event id 回调、回放参数和恢复 POST；
- UI 测试模拟“先收到 progress，再连接失败”，断言自动回放后显示最终回答和 Trace；
- 前端 lint、10 项单元测试、build 和 Chromium E2E 通过。
